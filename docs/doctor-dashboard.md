# Doctor Dashboard — 구현 및 데모 안내

기존 React 환자 문진과 연결한 의사 전용 **프론트엔드 데모**다. 실제 의사 인증, 서버 권한 검증, AI 서비스, EMR 연동, 진단·처방·위험도 판정·환자 알림은 구현하지 않는다.

## 실행과 경로

```sh
cd frontend
npm ci
npm run dev -- --host 127.0.0.1
```

- `/#/login`: 통합 로그인. 데모 의사 버튼으로 `doctor@example.test` / `Demo1234!`를 채운 후 로그인한다.
- `/#/doctor/login`: 이전 링크 호환을 위해 통합 로그인으로 이동한다.
- `/#/doctor`: 서울 시간 기준 오늘 예약 목록. 날짜·이름/식별번호·검토 필터.
- `/#/doctor/appointments/:id`: 예약 및 버전별 제출 문진 상세. 미로그인으로 직접 진입해도 로그인 후 해당 경로를 연다.
- 헤더의 별도 의사 로그인·환자 서비스 링크는 제거했다. 인증 결과의 역할에 따라 환자는 `/my`, 의사는 `/doctor`로 이동한다. 회원가입은 환자 계정만 생성한다.

오늘 목록의 Ari는 검토 대기, Bo는 기존 검토 완료, Casey는 문진 미제출, Drew는 요약 생성 중, Ellis는 생성 실패 사례다. 모두 합성 이름과 문진이다. 미제출 사례에는 원문·요약·메모 입력이 없다. 취소 예약 상태는 문진 검토 상태와 별도로 보인다.

## 작업 흐름

1. 환자를 검색하고 예약을 선택한다. 넓은 화면은 목록과 상세를 함께, 700px 이하에서는 개별 화면으로 표시한다.
2. 요약의 **View original answers**를 선택한다. 제출 시 고정한 답변 ID로 실제 원문을 강조하고 포커스를 이동한다. 전체 원문도 읽을 수 있다.
3. 메모를 작성하고 저장한다. 메모는 제출본 단위이며 환자 답변/요약을 변경하지 않는다. 이동 시 저장·변경 취소·계속 작성 중 선택한다. 새로고침/탭 닫기는 브라우저 기본 미저장 경고를 사용한다.
4. **Mark as reviewed**를 명시적으로 선택한다. 저장 성공 후 목록과 상세가 갱신된다. 진단 확정이나 사실 검증을 뜻하지 않는다.
5. 상세 하단 Demo controls에서 새 제출본을 시뮬레이션한다. 현재 버전을 유지한 채 새 버전 알림이 뜬다. 새 제출본은 검토 대기, 빈 메모로 시작하고 과거 메모·검토 이력은 버전 선택으로 다시 확인한다.
6. 같은 조작 영역에서 다음 메모·검토 저장 또는 조회를 실패시킬 수 있다. 실패 후 입력을 보존하며 다시 시도한다. 요약 생성 실패도 원문을 열고 재시도할 수 있다.

## 시각·상호작용 설계

기존의 차분한 녹색, 타이포그래피, 입력·버튼 규칙을 재사용했다. 정보 순서는 **환자 목록 → 고정 환자 식별정보 → 요약/원문 → 메모/명시적 검토**다. 통계·위험 점수·장식 차트 없이 구분선으로 읽기 영역을 나눴다. 선택 행 강조, 원문 패널 펼침과 근거 포커스, 고정 환자 헤더가 핵심 상호작용이다. 불필요한 모션을 넣지 않고 reduced-motion 설정을 존중한다.

원문 자유서술·이름·의사 메모는 언어 변경 시 수정하거나 번역하지 않는다. UI와 응답 상태만 공통 `en.json`/`ko.json`의 `doctor.*` 키로 번역한다. 기존 localStorage 언어 설정과 English 기본값, `English → korean` 선택 순서, `html lang`, 서울 시간대 정책을 그대로 사용한다.

## 데이터와 접근 경계

`src/doctor/service.js`는 UI에서 교체 가능한 비동기 mock 서비스다.

- 환자·의사가 `account/service.js`의 단일 인증 상태와 `visit-notes-auth-v2` 세션을 공유한다. 1시간 만료와 사용자 ID·역할·세션 세대(epoch)를 검사한다. 계정 전환·로그아웃·만료 시 기존 요청을 무효화하고 보호 화면의 상태를 비운다.
- 초기화 시 기존 `jinryo-session-demo-v1`, `visit-notes-doctor-session-v1` 로그인 정보는 모두 폐기하여 재로그인을 요구한다. 환자 문진(`jinryo-account-demo-v1`)과 의사 메모·검토(`visit-notes-doctor-v1`)는 보존한다. 새 세션은 사용자 ID와 만료 시각만 저장하며 역할은 계정 정보에서 복원한다.
- 복귀 경로는 역할별 내부 경로 허용 목록으로 검사한다. 상세 ID의 소유권도 데이터 서비스에서 검사한다. 외부 URL과 다른 역할의 경로는 역할별 홈으로 대체한다.
- 예약의 `doctorId` 할당을 목록·상세·메모·검토 작업마다 검사한다. 없는 ID와 다른 의사 ID는 같은 `NOT_FOUND`를 반환한다. **브라우저 코드의 데모 검사이며 서버 권한 검증이 아니다.**
- 환자 서비스의 `doctorDemoSource()`는 기존 `patient-a`, `patient-b`에 명시적으로 연결된 예약과 `status: sent`인 스냅샷만 반환한다. 작성 중/작성 완료지만 미전달인 답변, 신규 가입/익명 사용자의 문진은 반환하지 않는다.
- 예약에 연결된 제출본만 자동 수집하며 같은 스냅샷 ID/제출 시각을 중복 수집하지 않는다. 기존 환자 페이지의 읽기 전용 전달 기록 정책은 유지한다. **환자 화면에 재제출 기능을 새로 추가하지 않았으므로 후속 제출본 수신은 의사 데모 조작으로 재현한다.**
- 기존 환자 데모 예약은 오늘이 아닐 수 있다. 환자 예약 화면에서 날짜를 확인하고 의사 목록 날짜를 맞추면, 제출 전에는 미제출로, 전달 시뮬레이션 후에는 제출본으로 표시된다. 같은 탭에서 의사 영역을 다시 열거나 3초 주기 동기화 시 반영한다. 예약 미연결 제출본은 의사 예약 목록에 표시하지 않는다.
- 스냅샷 답변은 제출 시 복제한다. 답변 ID는 `submissionId:field`로 생성하여 저장하며 요약 섹션의 `refs`는 그 답변 ID를 가리킨다. 현재 mock 요약은 답변을 그룹화한 결정적 투영이다. 별도의 LLM 추론이나 신뢰도, 모순 판정은 수행하지 않는다. 미확인 상태/이름·용량 누락을 추가 확인 섹션에 노출한다.
- 검토 이력은 `doctorId`, `submissionId`, `submissionVersion`, `summaryId`, `summaryVersion`, `reviewedAt`를 저장한다. 최신 제출본인지 저장 시 다시 검사한다. 새 제출본이 도착한 뒤 이전 버전을 검토하려 하면 `NEW_VERSION`으로 거절한다. 중복 검토는 동일 기록을 반환한다.
- 노트는 제출본별 전체 텍스트 저장이다. UI는 중복 저장을 잠그고 이동 후 늦은 응답을 버린다. 실서버의 다중 탭/다중 사용자 동시 편집 충돌 해결은 구현하지 않는다.

## 저장 및 mock 인터페이스

- `visit-notes-doctor-v1` (sessionStorage): 가상 예약, 제출본, 원문, 메모와 검토 이력. 동일 탭 새로고침 시 복원된다. 저장소 차단 시 메모리에서만 유지된다.
- `visit-notes-doctor-session-v1` (sessionStorage): 데모 의사 ID와 만료 시각. 비밀번호를 저장하거나 기록하지 않는다.
- 로그아웃은 인증 세션과 화면 작업 상태를 제거한다. 저장된 가상 기록은 같은 의사가 다시 로그인하면 조회할 수 있다. 실제 민감정보 보관 체계가 아니다.
- `visit-notes-language` (localStorage): 기존 공통 언어 선호도.

| 서비스 메서드 | 용도 |
|---|---|
| `login(email, password)`, `logout()`, `scope()` | 별도 데모 의사 세션 |
| `list(scope, date)` | 할당 예약과 최신 제출/검토 상태. 원문은 포함하지 않음 |
| `detail(scope, appointmentId)` | 접근 가능한 예약과 제출본 이력 |
| `saveNote(scope, appointmentId, submissionId, text)` | 해당 제출본 메모 저장 |
| `review(scope, appointmentId, submissionId, summaryId)` | 최신 제출본의 명시적 검토 |
| `retrySummary(scope, appointmentId, submissionId)` | 가상 요약 상태 완료 |
| `simulateSubmission`, `failNext`, `slowNext`, `expire` | 데모 및 테스트 전용. 실제 API 대상 아님 |

실제 API 연동 시에는 서버 인증/역할·진료 배정 검사, 환자 제출본의 불변 저장 및 원문 참조, 서버 시각·감사 로그, 메모 버전/ETag 충돌 제어, 검토 멱등성, 제출 이벤트 전달과 오류 계약이 필요하다. 기존 FastAPI 세션 API를 의사용 인증 API처럼 사용하지 않았다.

## 검증

```sh
cd frontend
npm run lint
npm run test
npm run build
npm run test:e2e
```

새 단위 테스트는 의사 접근 범위, 미제출 비노출, 원문 불변/참조, 버전별 검토·중복 요청, 저장 실패·재시도, 로그아웃/만료 후 늦은 응답, 요약 실패, 환자 스냅샷 연계와 새로고침 복원을 다룬다. 브라우저 테스트는 원문 이동, 메모/검토/새 제출본, 미저장 보호, 언어 전환, 빠른 환자 전환, 권한 없는 ID, 세션 만료와 360/900/1440px 화면을 포함한다.
