# 진료노트 UX/UI와 구현 기록

## 설계 방향

따뜻한 흰색과 녹색을 사용한 조용한 작성 공간이다. 홍보용 히어로·통계·장식 차트 대신 질문을 중심으로 배치했다. 넓은 화면은 단계 탐색·작성 영역·짧은 메모의 3열, 360px에서는 단계 표시와 한 열 작성 영역으로 바뀐다. 버튼을 하단에 고정하지 않아 입력과 오류를 가리지 않는다.

정보 순서는 시작 안내 → 방문 이유 → 증상 경과 → 관련 정보 → 검토 → 완료다. 가상 예시는 방문 이유를 채우고, 명시적으로 알려준 시작 시점은 그대로 재사용한다. 한 화면에 한 질문을 제시하되 약 이름·용량, 알레르기 원인·반응은 함께 입력한다. 의료적 추론 없이 환자가 작성한 문자열을 요약한다.

완료 백분율과 총 질문 수는 표시하지 않는다. 네 큰 단계와 작성 완료 표시만 제공한다. 긴 채팅 인사 없이 선택과 자유 입력을 병행한다. 이 방식의 선호도와 완료시간 개선은 아직 검증되지 않은 가설이다.

180ms 화면 전환과 선택 상태 전환만 사용한다. OS의 동작 줄이기를 따른다. UI의 재사용 가능한 원형 라디오·입력·버튼·구분선으로 구성하고, 반복적인 카드 그리드를 사용하지 않았다.

## 데이터와 수정 규칙

| 상태 | 요약 표시 |
| --- | --- |
| unasked | 아직 질문하지 않음 |
| unanswered | 미응답 |
| none | 없음 |
| unknown | 모름 |
| declined | 답변 원하지 않음 |
| answered | 사용자가 입력하거나 선택한 값 |

빈 문자열을 ‘없음’으로 바꾸지 않는다. 약·알레르기는 ‘있어요’를 선택한 뒤 이름·상세 정보가 비어 있으면 각각 모름으로 표시한다. 비활성 항목의 입력은 요약에서 제외한다. 빈도는 부모 경과 변경 시 초기화하며 다시 활성화될 때 묻는다.

검토 화면에서 개별 섹션을 수정하고 즉시 돌아올 수 있다. 모든 답변 변경은 검토 확인과 전달 상태를 해제한다. 아직 묻지 않은 활성 질문은 검토에서 링크로 확인할 수 있고, 확인 전에는 전달하지 못한다. 요약에서 시작 시점·경과·빈도·불편 정도·일상 영향을 각각 수정할 수 있다.

요약 생성과 전달은 Promise 기반 mock이며 요청 토큰·revision·동기 잠금으로 오래된 응답과 중복 요청을 제어한다. 검토는 최신 공통 상태로 렌더링한다. 실패는 페이지 내 alert로 알리고 입력·현재 위치를 유지한다.

## 참고 근거

직접 확인한 자료의 필요한 원칙만 적용했다. 브랜드나 로고는 복제하지 않았다.

- [NHS Question pages](https://service-manual.nhs.uk/design-system/patterns/question-pages): 한 번에 한 질문, 유효한 모름 응답, 입력 재사용, 브라우저 뒤로가기. 이 프로토타입은 단일 질문과 직접 입력을 결합하고 명시적 시작 표현을 재사용한다.
- [NHS Check answers](https://service-manual.nhs.uk/design-system/patterns/check-answers/): 제출 전에 응답을 확인하고 각 항목을 수정하는 흐름. 요약 섹션마다 수정 버튼을 제공한다.
- [W3C Multi-page Forms](https://www.w3.org/WAI/tutorials/forms/multi-page/): 논리적 단계 구성과 진행 안내. 동적 질문 수 대신 큰 단계와 완료 상태를 보여준다.
- [W3C User Notifications](https://www.w3.org/WAI/tutorials/forms/notifications/): 명시적 오류 설명, 입력과 오류 연결, 동적 안내. aria-invalid·aria-describedby·role=alert·live status와 화면 제목 포커스를 적용했다.

제공된 나머지 연구·제품 자료의 전체 내용은 이번 구현에서 검토하지 않았다. 임상적 검증이나 진료시간 단축을 주장하지 않는다.
