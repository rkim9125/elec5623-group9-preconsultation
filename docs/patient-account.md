# 환자 계정·예약·문진 관리 프로토타입

기존 React 18/JSX, Vite 8, 스타일 토큰과 hash 탐색 방식을 유지했다. 기존 문진 화면을 다시 만들지 않고 `App`에 계정용 저장 어댑터를 추가했다. 기존 백엔드에는 인증·예약·사용자별 목록 API가 없어 이번 기능은 독립적인 브라우저 mock이다. 백엔드 API와 의료 판단 로직은 변경하지 않았다.

## 화면과 경로

실행: `cd frontend && npm ci && npm run dev`. 기본 주소는 `http://127.0.0.1:5173`.

| hash 경로 | 화면 |
| --- | --- |
| `#/login` | 이메일·비밀번호 로그인, 표시/숨기기, 가상 계정 입력 |
| `#/signup` | 이름·이메일·비밀번호·확인으로 데모 가입 |
| `#/my` | 가까운 예정 예약, 이어 쓸 문진, 최근 문진 |
| `#/appointments` | 예정·지난 예약·취소 목록 |
| `#/appointments/:id` | 예약 상세와 문진 작성·이어서 작성·보기 |
| `#/intakes` | 전체·작성 중·작성 완료·전달 완료 필터 |
| `#/intakes/:id` | 문진 상세, 연결 예약, 전달 당시 읽기 전용 요약 |
| `#/intakes/:id/edit/:step` | 기존 문진 화면 재사용, 저장된 답변·단계 복원 |
| `#/account` | 이름·이메일, 로그아웃, 현재 계정의 가상 기록 초기화 |
| `#start`, `#reason` 등 | 기존 비로그인 문진 흐름 |

보호된 화면에서 로그인으로 이동하면 `returnTo`에 앱 내부 경로를 보관한다. 복귀 경로는 명시적인 경로 패턴만 허용하고 외부 URL, 상대 경로 탐색, 잘못된 경로는 마이페이지로 대체한다.

## 데모 체험

로그인 화면에서 아래 계정 버튼을 누르면 이메일과 공통 비밀번호 `Demo1234!`가 입력된다. 로그인 버튼을 눌러 진행한다.

| 계정 | 이메일 | 준비된 정보 |
| --- | --- | --- |
| 데모 가람 | `garam@example.test` | 예정·지난·취소 예약, 작성 중·작성 완료·전달 완료 문진 |
| 데모 나래 | `narae@example.test` | 가람과 다른 가상 병원·예약·작성 중 문진 |
| 데모 새봄 | `empty@example.test` | 예약·문진이 없는 초기 상태 |

모든 이름과 병원은 가상이다. 가입한 새 계정에는 예약이나 문진을 자동 생성하지 않는다. 예약 없는 문진은 명시적으로 ‘예약 없이 문진 작성’을 선택할 때만 만든다.

목록 하단 **데모 테스트**에서 다음 조회 실패, 느린 조회(1.8초), 세션 만료를 체험한다. 로그인·회원가입의 데모 테스트는 다음 인증 요청을 한 번 실패시킨다. 입력 오류·인증 실패 이후 이메일은 보존한다. 비밀번호는 실패 후 비운다.

## 데이터와 인증의 유지 범위

- 실제 보안 인증이 아니다. 화면 보호와 mock 서비스의 소유자 검사는 서버의 권한 검증을 대신하지 않는다. 개발자 도구에서 읽을 수 있는 가상 데이터이므로 실제 개인정보·실제 비밀번호를 사용하지 않는다.
- 기본 조회·인증 지연은 400ms. 예약·문진 응답은 현재 사용자의 ID와 세션 세대(epoch)를 검사한 뒤 반환한다. 로그아웃·계정 변경·만료 후 이전 세대의 응답은 폐기한다. 인증 확인 중에는 보호된 내용을 렌더링하지 않는다.
- 세 가상 계정은 코드에 고정되어 있다. 이 계정들의 가상 예약·문진은 같은 탭의 `sessionStorage` (`jinryo-account-demo-v1`)에서 새로고침 후 복원된다. 로그인 상태 (`jinryo-session-demo-v1`)에는 사용자 ID와 1시간 만료 시각만 기록한다.
- 새로 가입한 계정의 이름·이메일과 임시 검증 값은 현재 페이지 실행 메모리에만 존재한다. **새로고침 전에는 가입 → 로그인 → 문진 → 로그아웃 → 재로그인 가능**하다. 새로고침하면 새로 가입한 계정과 그 계정의 기록은 만료·정리되고 다시 가입해야 한다. UI에도 이 유지 범위를 안내한다.
- 비밀번호 원문과 확인값은 브라우저 저장소·로그에 기록하지 않는다. 가입 mock은 임의 salt를 사용한 SHA-256 검증 값을 메모리에서만 사용한다. 이것은 운영용 비밀번호 저장 설계가 아니다. 인증 화면을 나가면 입력 상태와 진행 중 요청을 폐기한다.
- 로그아웃하면 인증 상태, 표시 중인 데이터, 메모리 조회 캐시를 정리한다. 가상 계정의 저장된 기록은 다음 로그인 때 조회할 수 있도록 남는다. 브라우저 뒤로가기는 매번 인증 상태를 검사한다.
- ‘현재 계정의 데모 기록 초기화’는 확인 후 해당 계정의 예약·문진만 지운다. 이후에도 빈 상태를 유지하고 가짜 기록을 다시 생성하지 않는다. 다른 계정과 비로그인 문진은 건드리지 않는다.
- 비로그인 문진은 기존 `maeum-intake-demo-v1`와 별도의 단계 키를 사용한다. 로그인할 때 자동 귀속하지 않는다. 마이페이지에서 **내 계정으로 가져오기**를 선택하면 예약 미연결 문진으로 옮기고 비로그인 원본을 제거한다. 같은 입력을 중복 가져오는 요청도 기존 기록을 반환한다.

## 기록 규칙과 UX

넓은 화면에서는 왼쪽 계정 메뉴와 오른쪽 작업 영역으로 구성한다. 마이페이지의 다음 예약 한 곳에 강조색 면을 사용하고, 나머지는 구분선이 있는 목록으로 표현한다. 모바일은 화면을 가리지 않는 가로 메뉴와 한 열 목록을 사용한다. 기존 진료노트의 녹색·여백·문구 톤·입력·버튼을 재사용한다. 장식 차트나 통계 카드는 추가하지 않았다.

예약 상태(`scheduled`, `completed`, `cancelled`)와 문진 상태(`draft`, `completed`, `sent`)는 독립적이다. 예약 확정이면서 시각이 미래일 때만 예정에 분류한다. 취소는 항상 별도 탭이다. 시간이 지난 예약을 임의로 진료 완료로 바꾸지 않는다. 모든 일시는 한국 시간 `Asia/Seoul`로 표시한다.

문진은 기존 답변 모델을 보관하고 예약 ID를 선택적으로 연결한다. 동일 예약에서 시작을 반복해도 기존 문진을 반환한다. 문진의 단계·답변은 동일 저장소에 반영되어 홈·예약·문진 목록이 재조회 시 일치한다. 작성 완료는 활성 질문을 확인하고 요약 화면에 도달했다는 뜻이고, 검토 승인과는 별도다. 새로 필요한 질문이 아직 미확인 상태라면 작성 중으로 표시한다. 수정하면 기존 검토 승인이 해제된다.

전달 시뮬레이션이 완료되면 당시 요약과 시각을 별도 snapshot으로 고정한다. 이후 상세는 읽기 전용이며 직접 편집 URL을 입력해도 상세로 돌아간다. 저장 어댑터도 고정된 기록을 덮어쓰지 않는다. 실제 병원 전송이나 의사의 확인을 표시하지 않는다.

## 코드와 실제 API 교체

- `frontend/src/account/domain.js`: ID로 연결한 가상 자료, 예약 분류·정렬, 날짜, 복귀 경로 검사.
- `frontend/src/account/service.js`: 교체 가능한 인증·조회·저장 mock, 세션 세대 검사, 기록 보존.
- `frontend/src/account/Portal.jsx`: 인증 화면, 보호된 화면, 계정 메뉴·목록·상세.
- `frontend/src/account/router.jsx`: 기존 hash 탐색을 확장한 경로 알림·링크.
- `frontend/src/pages/patient/App.jsx`: 기존 문진을 그대로 사용하며 계정 저장 콜백과 목록 복귀만 연결.

운영 API 연동 시 필요한 작업: 서버 인증·세션 관리, 비밀번호 정책 및 안전한 자격 정보 저장, 사용자별 예약·문진 접근 통제, 응답 스키마 검증, 영속 저장, 서버 기준 시각과 예약 상태, 전달 snapshot·멱등성·동시 수정 제어, 실제 전송 결과와 실패 처리. 회원가입·예약 조회·문진 소유권에 대한 API 계약을 먼저 확정해야 한다. 관리자·예약 생성/변경/취소·결제·소셜 로그인·배포는 구현하지 않았다.
