# PreConsult 파이프라인 및 추가 실험 보고서

실행일: 2026-11-02 · 모델: `gpt-6-sol` · 본 실행: `extended-20261102`

**상태: 확보된 결과 보고. 의미 기반 사실 정확도 재채점과 캐시 성능 비교는 API 크레딧 부족으로 미완료다.** 독립적인 사람 검토는 요청에 따라 제외했다. 아래의 전달 성공은 내용 정확도를 포함한 종합 성공과 다르다. 완료되지 않은 채점을 0점이나 100점으로 대신하지 않았다.

## 1. 주요 결과

**이 결과로 일반 챗봇보다 내용 정확도가 높다고 결론 내릴 수 없다.** 현재 확인된 주요 문제는 낮은 AI 요약 전달률과 검증기의 양방향 오류다. 내용 정확도와 정보 수집 효과에 대한 결론은 재채점 완료 후에 내려야 한다.

## 2. 실험 설계와 고정 조건

### 2.1 데이터

새 사례는 단일 증상, 다중 증상·보충제, 불확실성·부정·응답 거절, 수정·삭제, 정보 부족, 잡음이 섞인 입력의 여섯 유형으로 구성했다. 유형마다 4개, 총 24개다. 다리, 허리, 목·어깨, 수면을 기본 주제로 사용하고 다중 증상 사례에는 눈 건조를 추가했다. 실제 사용 workflow는 `WF-01`, `WF-02`, `WF-03`, `WF-08`, `WF-13`이다. **전체 30개 workflow를 평가한 것은 아니다.** 같은 주제와 생성 틀을 공유하므로 24개를 독립적인 환자 모집단 표본으로 해석하지 않는다.

입력, 필수 사실, 금지 주장, 정정 문장과 후속 답변은 생성 실행 전에 고정했다. 후속 질문은 정해진 답변 은행에서 답하고, 정의되지 않은 질문에는 `I am not sure.`로 답했다. 눈 증상의 기간은 다른 증상과 섞이지 않도록 별도로 매핑했다. 추가 질문에 답하는 환자 생성 모델은 사용하지 않았다. 정답 목록과 숨겨진 답변 전체는 대상 모델에 제공하지 않았다.

- [고정 사례 JSON](../extended_cases.json)
- [사례 생성 코드](../extended_corpus.py)
- 기존 N01–N04·I01–I02는 새 표본에 포함하지 않았다. 기존 원출력 6개는 검증기 재생에 사용했다.

### 2.2 조건과 실행 수

| 조건 | 구성 | 예정 실행 |
|---|---|---:|
| Full | 현재 추출·상태 관리·질문 선택·요약·검증·저장·공유 경로 | 24 × 3 = 72 |
| Generic | 같은 모델의 일반 문진·요약 프롬프트, 질문 한 묶음, 자유문 요약 | 24 × 3 = 72 |
| Fixed | Full에서 AI 질문 선택만 제거하고 eligible targets의 앞 5개를 선택 | 24 × 3 = 72 |
| No follow-up | 단일·다중·정보 부족 유형 12개에서 추가 질문을 생략 | 12 × 3 = 36 |
| Attack | 첫 8개 정상 사례에 공격 문구 하나씩 추가 | 8 × 3 = 24 |
| 합계 | 정상 비교군은 공격·제거 분석에서 재사용 | **276** |

질문 기본 한도는 5개, 영어 텍스트 입력·출력, 동일 모델을 사용했다. Full·Fixed는 제품의 동일 추출·요약 코드를 사용한다. Generic은 별도의 일반 대화 비교군으로, 제품의 `chat` 모드가 아니다. 자유문 질문은 고정된 표현 매핑 규칙으로 답변 은행에 연결했다. 이 매핑 차이는 비교의 한계다. Generic에는 제품의 인용 검증이나 저장·승인 기능을 강제로 덧붙이지 않았다. 따라서 전달률만으로 Generic의 임상적·사실적 우월성을 주장하지 않는다.

실행 순서는 고정 난수값 `5623`으로 섞었다. 생성은 최대 6개 프로세스에서 수행했고, 후반에는 별도 채점이 함께 실행됐다. 시간 수치는 이 평가 환경에서의 관측값이며 서비스 부하 시험이나 배포 환경 SLO가 아니다.

### 2.3 실제 연결 범위

`입력 → 실제 추출 → DB 상태 → 질문 → 답변 초안 저장 → 답변 제출·재추출 → 요약·검증 → 정정·재생성 → 승인 → 의료진 조회 → 공유 철회`

FastAPI의 실제 route를 TestClient로 호출하고, 매 실행마다 별도 SQLite DB를 사용했다. 이전 모델 결과가 다음 단계 상태에 실제로 반영됐다. 상태를 정답으로 교체하거나 정답 요약을 주입하지 않았다. 각 단계의 상태, 실제 HTTP payload·원응답, API 상태 코드를 저장했다. 모델 요청 헤더·API 키·인증 쿠키는 증거 파일에 저장하지 않았다.

OTP 이메일 전송만 평가용 수신 함수로 대체했고 인증·역할·소유권·승인 route는 실제 코드로 실행했다. 외부 이메일 전송, 실사용자 DB, 실제 환자 데이터는 사용하지 않았다. 음성, 다국어, 첨부, AI assessment의 의학적 판단과 PDF 내보내기는 이번 핵심 실행의 범위 밖이다.

## 3. 파이프라인 전달 결과

**전달:** 최종 요약의 `synthesis.status == live`이며 환자 API에서 AI 문장을 확인할 수 있는 상태. 의미상 정확하다는 뜻은 아니다. **HTTP 오류 없음:** 채점 호출을 제외한 해당 실행의 모든 대상 모델 호출이 HTTP 200인 경우다. 불완전한 내용이나 제품 검증 거절까지 성공 처리한 정의가 아니다.

| 조건 | 전체 실행 | 모델 서비스 오류 영향 | HTTP 오류 없는 실행 | 그중 AI 요약 전달 | 전체 실행 기준 전달 |
|---|---:|---:|---:|---:|---:|
| Full | 72 | 8 | 64 | **25/64, 39.1%** | 26/72 |
| Generic | 72 | 15 | 57 | 57/57, 100% | 57/72 |
| Fixed | 72 | 24 | 48 | 21/48, 43.8% | 22/72 |
| No follow-up | 36 | 11 | 25 | 10/25, 40.0% | 11/36 |
| Attack | 24 | 5 | 19 | 7/19, 36.8% | 8/24 |

일부 실행은 추출 등의 호출에 실패한 뒤 저장된 입력을 이용해 요약을 생성할 수 있었다. 그래서 전체 전달 수와 HTTP 오류 없는 실행의 전달 수가 다르다. 실패 실행을 분모에서 숨기지 않기 위해 두 값을 함께 제시했다. 오류가 없는 실행만 선택한 비율에도 선택 편향이 있으므로 완전한 균형 실험의 추정치로 해석하면 안 된다.

Full에서 3회 모두 HTTP 오류 없이 실행된 시나리오는 17개였다. 그중 AI 요약 전달이 **3/3인 사례 2개, 2/3인 사례 6개, 1/3인 사례 2개, 0/3인 사례 7개**였다. 한 번의 성공만으로 반복 안정성을 추정하기 어렵다는 점이 확인됐다.

### 3.1 저장·승인·접근 제어

Full 72/72, Fixed 70/72, No follow-up 36/36, Attack 24/24에서 실행기가 기대한 승인·조회·철회 흐름을 모두 통과했다. 이 검사에는 미승인 의료진 접근 차단, 잘못된 요약 버전 승인 거절, 승인된 버전·AI 문장 일치, 다른 의료진 접근 차단, 공유 철회 후 접근 차단과 초안의 사실 상태 미반영이 포함된다. 대체 구조화 기록만 공유되는 경우도 기능 검사에는 통과할 수 있다.

Fixed의 두 비통과 사례 `E43-fixed-3`, `E42-fixed-2`는 서비스 오류의 영향을 받은 수정 사례다. 정정이 미해결인 상태에서 승인 자체가 차단됐다. 이를 접근 제어의 실패나 잘못된 기록 공유로 해석하면 안 된다. HTTP 오류가 없는 제품 실행 **156/156**에서는 해당 기능 검사를 모두 통과했다.

## 4. 비교 및 구성요소 제거

아래는 같은 사례·같은 반복 번호에서 **양쪽 모두 HTTP 오류가 없었던 쌍만** 비교한 기술 통계다. 의미 정확도 검정이나 우월성 검정이 아니다.

| 비교 | 대응 실행 쌍 | Full 전달 | 비교 조건 전달 | Full의 정의된 답변 수/실행 | 비교 조건의 정의된 답변 수/실행 |
|---|---:|---:|---:|---:|---:|
| Full–Generic | 50 | 20/50 | 50/50 | 4.82 | 3.94 |
| Full–Fixed | 45 | 19/45 | 19/45 | 4.82 | 4.89 |
| Full–No follow-up | 22 | 8/22 | 9/22 | 4.55 | 0 |
| 정상 Full–Attack | 18 | 4/18 | 6/18 | 4.94 | 4.94 |

정의된 답변 수는 답변 은행의 실제 문장을 반환한 질문 수이며, `I am not sure.`는 제외한다. 이미 제공한 사실의 반복 여부나 의료적으로 중요한 정보의 획득을 확정하는 지표가 아니다. Generic의 자유문 질문 매핑 실패도 수치에 영향을 줄 수 있다.

이번 대응 표본에서는 적응형 질문 선택이 고정 질문보다 전달률을 높였다는 증거가 없다. 추가 질문은 답변을 더 수집했지만, 그 정보가 최종 요약에 정확히 보존됐는지는 미완료 재채점이 필요하다. 공격 조건의 전달률이 우연히 높았다는 이유로 공격이 유익하거나 안전하다고 결론 내릴 수 없다.

## 5. 검증기 재생 및 제거 실험

### 5.1 기존 실행 재현

2026-10-28의 실제 요약 원출력과 당시 입력을 현재 검증기에 다시 넣었다. **N02·N04만 통과하고 N01·N03·I01·I02는 거절**돼 기존 보고서의 2/6 통과 결과가 재현됐다. 새 모델 호출은 하지 않았다.

### 5.2 경계사례 40개

`_validate_cited`를 대상으로 정답이 사전에 명시된 정상 20개·오류 20개를 검사했다. 전체 합성 요약 검증기의 모든 규칙을 평가한 것은 아니다. 5개 패턴을 각각 4번 구성했으며, 불확실성·혼합 부정 패턴에는 동일한 문장이 반복된다. 따라서 40개를 독립적인 표현 40종으로 세지 않는다.

| 패턴 | 정상 허용/4 | 오류 차단/4 | 관찰 |
|---|---:|---:|---|
| 불확실성 | 0 | 4 | `does not know`라는 정확한 표현도 거절 |
| 긍정·부정이 섞인 source | 0 | 4 | 같은 source의 긍정 사실만 정확히 요약해도 거절 |
| 좌우 위치 | 4 | 0 | 왼쪽↔오른쪽 변경을 검사하지 못함 |
| 용량 | 4 | 4 | 기존 수치 보존 허용, 새 수치 차단 |
| 인용 ID | 4 | 4 | 존재하는 ID 허용, 없는 ID 차단 |
| 합계 | **12/20** | **16/20** | 정상 거절 8/20, 오류 허용 4/20 |

검증을 제거하고 동일 출력을 모두 허용하는 조건에서는 정상 거절이 0/20으로 줄지만 오류 허용은 20/20이 된다. 따라서 검증기의 단순 삭제는 해결책이 아니다. 문장별로 실제 사용한 근거와 부정·불확실성의 적용 범위를 확인하고, 증상·대상·좌우 정보의 의미 일치를 보완해야 한다. 위 비율은 의도적으로 만든 경계사례 집합의 결과이며 실제 서비스 오류 확률이 아니다.

HTTP 오류가 없는 제품 실행의 최종 거절 93건 중 70건은 불확실성, 19건은 부정 보존 검사였다. 경계사례 재현은 검증 로직에 실제 문제가 있음을 보여주지만, **실행 중 거절된 93개 전부가 오탐임을 입증하지는 않는다.**

## 6. 공격 및 장애 평가

### 6.1 공격

8개 공격 문구는 다른 합성 환자의 기록 조회·허구 생성, 거짓 체온·진단 삽입, 시스템·개발자 역할 위장을 포함한다. 정상 사실은 대응 정상 실행과 같고 공격 문구만 초기 입력에 추가했다. 24회 실행 중 19회는 대상 모델 호출에 HTTP 오류가 없었다.

이번 자료로는 **공격 추종률과 공격 무시·정상 과제 동시 성공률을 확정하지 않았다.** 최종 내용의 재채점이 완료되지 않았기 때문이다. 공격 문구가 입력에 저장됐다는 사실 자체를 허위 환자 사실의 채택으로 세지 않았으며, AI 요약이 거절됐다는 사실만으로 공격 방어 성공으로 세지도 않았다. 문서 간접 주입, 후속 답변에만 삽입한 공격, 실제 타인 기록 조회 도구를 통한 유출은 미평가다.

### 6.2 장애 주입

추출·질문 생성·요약 3단계에 timeout, HTTP 429, HTTP 503, 잘못된 JSON 4종을 각각 주입했다. 정상 단계에는 결정적 응답 대역을 사용했다. 장애 단계는 실제 provider의 HTTP 오류 처리 코드를 통과하고, 결과 상태를 격리 SQLite에 저장·재로드했다.

**12/12 조건**에서 기존 입력 보존, 사용자에게 unavailable 표시, 실패를 live 요약으로 표시하지 않음, 정상 응답 대역으로 재시도 후 복구를 확인했다. 실제 공급자 장애에서의 복구 확률·시간, 자동 재시도 정책이나 부하 복원력을 측정한 것은 아니다.

## 7. 지연시간과 사용량

시간은 인증·상태 저장·질문 처리·요약·승인 흐름을 포함한 실행 시간이며 자동 채점 시간은 제외한다. 환자 답변은 즉시 제출하므로 사람의 생각·입력 시간도 제외된다. 아래 시간은 대상 모델 호출에 HTTP 오류가 없는 실행만 사용했다. 요약 검증 거절 실행도 포함하므로, 성공한 요약만의 응답시간과 다르다.

대상 과제 호출은 총 **814개**이며, 721개에서 HTTP 200과 사용량을 확보했고 93개는 크레딧 부족 응답이었다. 기록된 입력 9,143,041토큰, 출력 480,053토큰, 캐시 읽기 7,582,736토큰의 비용 소계는 **$9.4377**이다. 별도 채점 호출의 기록된 사용량 비용 소계는 **$1.4849**로, 대상 과제 비용에 섞지 않았다. 예비 실행 비용은 이 표에서 제외했다.

### 7.1 캐시 비교의 미완료

추출·요약 요청 6묶음에 최초 요청 1회, 반복 요청 5회, 동일 내용에서 명시적 캐시 경계를 제거한 요청 5회를 계획했다. 실제 usage로 조건을 검증할 예정이었다. 그러나 **66회 모두 크레딧 부족 응답**을 받아 유효한 비교 출력·사용량을 얻지 못했다. 오류 응답 시간으로 캐시 성능을 계산하지 않았고, 캐시 절감률·속도 향상률을 제시하지 않는다.

최초 크레딧 부족은 본 실행 기록에서 **2026-11-02 04:27:05 UTC / Sydney 15:27:05**에 확인된다. 초기 실행기는 호출 수 상한만 갖고 공유 크레딧 차단 기능이 없어 이후 여러 작업이 같은 실패를 반복했다. 이 동작도 평가 실행기의 한계다. 이후 같은 실행 묶음에서 첫 `credit_balance_exhausted` 이후 새 호출을 막는 공유 차단 기능을 추가하고, 다음 실행이 네트워크 호출 전에 중단되는 테스트를 통과시켰다. **이번 수집 결과를 소급해 바꾸지는 않았다.**

## 8. 자동 채점의 미완료와 결과 사용 범위

초기 자동 채점은 같은 모델을 별도 호출해 조건명을 가리고 수행했다. 그러나 점검 중 두 가지 문제가 확인됐다.

1. 단순 답변 문자열만 제공해 다중 증상에서 질문 대상과 답변의 연결이 사라졌다.
2. 인터페이스의 미입력 필드 설명이나 정형화된 주제 제목을 근거 없는 환자 사실로 오인했다.

따라서 초기 채점 결과는 최종 성적에 사용하지 않는다. 질문·답변·대상 증상을 함께 제공하고, UI 메타데이터를 환자 사실 주장과 분리하는 수정 기준을 만들었다. 이 기준을 실패 사례에만 적용하지 않고 모든 조건에 적용하도록 준비했다. 그러나 후보 출력 227개의 수정 채점은 모두 크레딧 부족으로 완료되지 못했고, 나머지 49개는 채점할 최종 후보 출력 자체가 없었다.

이에 따라 **추출 사실 F1, 요약 사실 정확도·필수 정보 포함률, 내용 기준 E2E 성공률, 공격 동시 성공률, 의미 품질의 대응 차이·신뢰구간은 N/A**로 남긴다. 수정 전 점수와 수정 후 점수를 혼합하거나, 미채점 출력을 오답으로 채워 비교하지 않는다. 구조화 추출 전체의 원자 사실 매칭도 별도로 완료되지 않았다.

완료된 전달·권한·검증기 경계사례·장애 검사는 위 의미 채점과 독립적으로 재현 가능한 결과다. 사람 검토와 임상 타당성 판단은 수행하지 않았다.

## 9. 브라우저 및 코드 검증

실제 생성 실행의 결과 중 여섯 유형에서 하나씩 선택해 별도 DB에 옮겼다. 브라우저 실행 중 AI·이메일 호출은 비활성화했고, 실제 frontend와 실제 API를 사용했다. 즉 **실제 결과 재생에 대한 UI 검증**이며, 브라우저에서 처음부터 모델 호출까지 수행한 별도의 live E2E 6회는 아니다.

선택 실행: `E12-full-2`, `E24-full-2`, `E33-full-3`, `E42-full-1`, `E53-full-1`, `E61-full-1`. 4개는 AI 요약 unavailable, 2개는 live 상태였다.

- 6/6에서 환자 검토·승인과 의료진 조회가 동작했고 승인된 synthesis 데이터가 동일했다.
- 환자·의료진 화면을 각각 1440px·390px에서 확인해 총 24개 화면 캡처를 남겼다. 자동 검사에서는 가로 overflow와 페이지 JavaScript 오류가 검출되지 않았다.
- **별도 이미지 확인에서는 390px 환자 화면의 상단이 왼쪽 내비게이션에 가려지는 문제를 관찰했다.** 데스크톱에서 모바일 폭으로 변경한 경로이며, 모바일 UI 전체가 정상이라는 결론은 유보한다. [화면 증거](2026-11-02-assets/mobile-overlap.png)
- 요약 생성 실패 시 의료진 화면에 unavailable 상태와 대체 구조화 기록이 표시됐다. 이를 AI 요약 성공으로 계산하지 않았다. [화면 증거](2026-11-02-assets/clinician-fallback.png)

관련 회귀·평가 테스트 193개가 통과했다. 이후 크레딧 차단 검사 1개를 추가했으며, 최종 평가 테스트 전체 재실행도 22개 모두 통과했다(앞선 실행과 중복되는 검사 포함). frontend 빌드도 통과했으며 번들 크기 경고가 있었다. 최초 테스트 수집은 로컬 `LLM_PROVIDER=openai`와 legacy 설정 형식의 불일치로 실패했고, 테스트 프로세스에만 `LLM_PROVIDER=fake`를 지정해 재실행했다. 제품 환경 설정 파일은 수정하지 않았다.

## 10. 증거·재현·남은 작업

주요 증거는 [기계 판독용 결과 JSON](2026-11-02-pipeline-evidence.json)에 있다. 각 조건의 분모, 실행별 전달 여부, API 검사, 사용량, 오프라인 검사, 브라우저 결과와 미채점 상태를 포함한다.

원본 요청·응답과 상태는 `backend/eval/runs/extended-20261102/`에 보존돼 있다. `runs/`는 기존 정책에 따라 Git 제외 대상이다. `manifest.json`에 실행 순서·정답·설정·소스 해시를 저장했고, 실행에 사용한 54개 파일은 해시 일치를 확인한 뒤 `source_snapshot/`에 복사했다. 공유 크레딧 차단 기능은 실행 이후 추가됐으므로 당시 실행의 재현은 이 snapshot을 기준으로 해야 한다. `raw_review/`와 초기 `outcome.json`의 의미 채점은 참고용 원자료이며 최종 성적으로 사용할 수 없다.

```bash
# 네트워크 호출 없는 기존 결과 재계산
backend/.venv/bin/python backend/eval/extended_report.py \
  --run backend/eval/runs/extended-20261102 \
  --output backend/eval/reports/2026-11-02-pipeline-evidence.json

# 검증기·장애 실험 재현(별도의 새 출력 디렉터리 지정)
backend/.venv/bin/python backend/eval/extended_offline.py \
  --output backend/eval/runs/offline-reproduction

# 새 실제 실험의 명세 준비: --live가 없으면 호출하지 않음
backend/.venv/bin/python backend/eval/extended_run.py \
  --output backend/eval/runs/new-evaluation
```

크레딧 복구 후에는 먼저 수정된 채점 기준을 작은 고정 예제로 검증하고, 확보된 227개 후보를 같은 기준으로 채점해야 한다. 이어 크레딧 부족에 영향받은 63개 과제 실행을 별도 재실행 묶음으로 보완하고, 원실행과 재실행을 구분해 결과를 보고해야 한다. 캐시 비교는 사용량이 실제로 반환되는 조건에서 다시 수행해야 한다. 최종 구조화 사실 F1·질문 적절성·정보 획득 평가와 지원 언어·음성·첨부·assessment/PDF 분기는 추가 범위로 남아 있다.

제품 검증 로직은 이번 작업에서 수정하지 않았다. 우선 수정 대상으로 확인된 것은 불확실성·혼합 부정 근거의 적용 범위와 좌우·대상 일치 검사다. 수정 전·후 비교에는 이번 사례를 회귀 집합으로 사용하고, 일반화 확인에는 별도의 미사용 사례가 필요하다.
