# PreConsult 파이프라인 및 추가 실험 — 성공 실행 기록 보고서

실행일: 2026-11-02 · 모델: `gpt-6-sol` · 원실행: `extended-20261102`

**최종 AI 요약 전달까지 완료한 성공 실행 120건을 선별해 작성했다.** 제품 조건의 파이프라인 실행은 63건, 일반 챗봇 비교 조건은 57건이다. 지연시간·호출 수·토큰·비용은 모두 이 120건에서 다시 계산했다. 기존 결과를 재집계했으며 새로운 모델 호출은 수행하지 않았다.

이 문서는 **성공 사례만의 부분집합 보고서**다. 포함 건수나 검사 통과 건수를 전체 시도의 성공률로 해석하지 않는다. 여기서 성공은 요약 전달과 기능 흐름의 완료를 뜻하며, 내용의 사실 정확도나 임상적 타당성을 뜻하지 않는다. 전체 평가 맥락은 [원본 보고서](2026-11-02-pipeline-evaluation.ko.md), 실행별 근거는 [결과 JSON](2026-11-02-pipeline-evidence.json)에 보존돼 있다.

## 1. 성공 실행 선정 기준

다음 기준을 모두 만족하는 기록을 포함했다.

1. 자동 채점 호출을 제외한 해당 과제의 모든 모델 호출이 HTTP 200으로 완료됐다(`service_available == true`).
2. 최종 AI 요약이 전달됐다(`delivery == true`). 제품 조건은 최종 `synthesis.status == live`, Generic은 최종 요약 응답 수신을 의미한다.
3. 제품 조건은 승인·의료진 조회·내용 일치·접근 제어·공유 철회 검사를 모두 통과했다(`api_workflow_pass == true`). Generic에는 제품의 공유 기능이 없어 이 기준을 적용하지 않았다.

실행 단위는 **시나리오 × 조건 × 반복 번호**다. 별도 채점 단계까지 포함하는 최상위 `status` 대신 위 과제 단계별 근거로 선정했다. 선정된 120건의 원응답·최종 출력·시간을 대조했고, 제품 63건의 실제 상태와 기능 검사 결과도 확인했다.

| 조건 | 실행 구성 | 포함된 성공 실행 | 포함된 고유 시나리오 |
|---|---|---:|---:|
| Full | 현재 제품의 추출·질문 선택·요약·검증·공유 | 25 | 13 |
| Generic | 같은 모델의 일반 문진·자유문 요약 | 57 | 23 |
| Fixed | AI 질문 선택을 고정 질문 선택으로 대체 | 21 | 12 |
| No follow-up | 추가 질문 생략 | 10 | 7 |
| Attack | 초기 입력에 공격 문구 추가 | 7 | 4 |
| 합계 | 조건 간 동일 시나리오 재사용 | **120** | **24** |

고유 시나리오 수는 조건 사이에 중복되므로 열의 값을 합산하지 않는다. 모든 조건을 합친 성공 기록에는 여섯 유형이 포함된다. Full의 성공 기록은 단일 증상·수정·삭제·정보 부족·잡음 입력 유형에서 확보됐다.

## 2. 실험 구성

고정 합성 시나리오 24개를 사용했다. 유형은 단일 증상, 다중 증상·보충제, 불확실성·부정·응답 거절, 수정·삭제, 정보 부족, 잡음 입력이다. 시나리오별 입력·정정 문장·후속 답변 은행은 생성 전에 고정했고, 같은 조건을 최대 3회 반복했다. 사례 원문은 [고정 사례 JSON](../extended_cases.json)에서 확인할 수 있다.

영어 텍스트 입력·출력과 동일 모델을 사용하고, 질문을 사용하는 조건에는 기본 한도 5개를 적용했다. Full과 Fixed는 같은 제품 추출·상태 관리·요약 코드를 사용하며 질문 선택 방식만 다르다. No follow-up은 추가 질문을 생략한다. Attack은 정상 사실에 공격 문구를 추가한다. Generic은 별도의 일반 문진·요약 프롬프트를 사용한다.

실행 순서는 고정 난수값 `5623`으로 섞었고 생성 작업은 최대 6개 프로세스에서 수행했다. 모델 결과가 다음 단계의 실제 상태에 반영되도록 FastAPI route와 실행별 SQLite DB를 연결했다. OTP 이메일 발송은 평가용 수신 함수로 대체했으며, 인증·역할·소유권·승인 route는 실제 코드를 사용했다.

| 비교 | 양쪽 성공 대응 쌍 | 정의된 답변 수 평균 | 과제 수행 시간 평균 |

정의된 답변 수는 답변 은행에서 `I am not sure.` 이외의 답변을 반환한 질문 수다. 답변의 중복 여부, 임상적 중요도, 최종 요약의 정보 보존을 평가한 수치는 아니다. Generic은 자유문 질문을 표현 매핑 규칙으로 답변 은행에 연결하므로 제품의 구조화 질문과 응답 방식에 차이가 있다.

이 표는 완료된 실행에서 관측한 작업량과 시간의 비교다. 성공 여부로 선별한 표본이므로 조건 간 성공률, 정확도 우월성 또는 구성요소의 인과적 효과를 추정하지 않는다. Attack의 7건도 공격 문구가 있는 입력에서 요약 전달·공유 경로를 완료한 기록이며, 공격 방어의 의미적 성공 판정과는 구분한다.

## 5. 성공 실행의 지연시간과 사용량

각 조건에서 선정된 성공 실행만으로 시간과 비용을 함께 집계했다. 시간은 해당 조건의 과제 수행 구간이며 제품 조건에는 인증·저장·승인 흐름이 포함된다. 별도 자동 채점 시간과 사람의 생각·입력 시간은 제외했다. Generic은 제품의 승인·공유 경로를 포함하지 않는다.

| 조건 | 시간·비용 분모 | p50 | p95 | 대상 모델 호출 | 추정 비용 소계 | 실행당 추정 평균 |
|---|---:|---:|---:|---:|---:|---:|
| Full | 25 | 26.71초 | 48.14초 | 114 | $1.5326 | $0.0613 |
| Generic | 57 | 6.37초 | 8.11초 | 114 | $0.2018 | $0.0035 |
| Fixed | 21 | 22.30초 | 41.45초 | 73 | $1.0035 | $0.0478 |
| No follow-up | 10 | 16.66초 | 22.31초 | 20 | $0.3092 | $0.0309 |
| Attack | 7 | 27.16초 | 30.66초 | 28 | $0.3786 | $0.0541 |
| 합계 | **120건** | — | — | **349회** | **$3.4256** | **$0.0285** |

p50·p95는 정렬한 관측값의 위치 `(n−1) × p`에서 선형 보간했다. 반복 실행의 병렬 처리와 별도 채점의 동시 실행 영향을 포함한 관측값이다.

선정된 실행의 대상 모델 호출 349회에서 모두 usage가 기록됐다.

| 사용량 항목 | 성공 실행 합계 |
|---|---:|
| 입력 토큰 | 3,513,669 |
| 출력 토큰 | 175,658 |
| 입력 중 캐시 읽기 토큰 | 2,976,869 |
| 입력 중 비캐시 토큰 | 536,800 |

비용은 원본 보고서와 같은 **2026-10-28 가격 가정**을 적용했다. 백만 토큰당 일반 입력 $2, 캐시 읽기 $0.20, 출력 $10이며, 계산식은 다음과 같다.

`(536,800 × $2 + 2,976,869 × $0.20 + 175,658 × $10) / 1,000,000 = $3.4255538`

현재 가격이나 청구서를 검증한 금액은 아니다. 별도 자동 채점·예비 실행은 이 비용에 포함하지 않았다. 캐시 읽기 토큰은 실제 usage의 관측량이며, 캐시 유무의 통제 실험으로 계산한 절감률은 제시하지 않는다.

## 6. 추가 실험의 통과 기록

아래 실험은 생성 실행 120건과 단위가 다르므로 별도 집계했다. 검증기는 기대 판정과 실제 판정의 일치, 장애 주입은 보호·복구 조건 충족, 브라우저는 승인·조회 기능 완료를 각각 성공 기준으로 삼았다.

### 6.1 검증기 기대 판정과 일치한 기록

`_validate_cited` 경계사례 중 기대 판정과 실제 판정이 일치한 **28건**을 포함했다.

| 통과한 검사 유형 | 확인된 동작 | 포함 기록 |
|---|---|---:|
| 불확실성 의미를 바꾼 출력 | 오류 출력 차단 | 4건 |
| 원문 부정과 충돌하는 출력 | 오류 출력 차단 | 4건 |
| 원문과 좌우 위치가 같은 출력 | 정상 출력 허용 | 4건 |
| 원문 용량을 유지한 출력 | 정상 출력 허용 | 4건 |
| 근거에 없는 용량 수치를 넣은 출력 | 오류 출력 차단 | 4건 |
| 존재하는 근거 ID를 인용한 출력 | 정상 출력 허용 | 4건 |
| 존재하지 않는 근거 ID를 인용한 출력 | 오류 출력 차단 | 4건 |
| 합계 | 정상 허용 12건 + 오류 차단 16건 | **28건** |

같은 문장이나 패턴의 반복을 포함한 통과 기록 수다. 검증기의 전체 정확도나 서로 독립적인 표현 28종을 의미하지 않는다. 기존 실제 요약 원출력의 재생에서는 `N02 / call-0006`, `N04 / call-0013` 두 기록의 검증 통과를 확인했다. 이 재생에는 새 모델 호출을 사용하지 않았다.

### 6.2 장애 주입의 보호·복구 검사

추출·질문 생성·요약 단계별로 네 종류의 장애를 주입한 **12개 조건**에서 다음 검사가 통과했다.

| 주입 단계 | 통과한 장애 조건 | 통과 기록 |
|---|---|---:|
| 추출 | timeout, HTTP 429, HTTP 503, 잘못된 JSON | 4건 |
| 질문 생성 | timeout, HTTP 429, HTTP 503, 잘못된 JSON | 4건 |
| 요약 | timeout, HTTP 429, HTTP 503, 잘못된 JSON | 4건 |

각 기록에서 기존 입력 보존, unavailable 상태 표시, 실패 응답을 live 요약으로 표시하지 않음, 정상 응답 대역을 이용한 재시도 후 복구를 확인했다. 실제 provider 오류 처리 코드를 거쳐 SQLite에 저장·재로드했다. 이 결과는 통제된 장애 주입 검사의 통과 기록이며 실제 공급자 장애의 복구 확률·시간을 측정한 값은 아니다.

### 6.3 성공 결과의 브라우저 재생

선정된 생성 실행 중 live 요약을 가진 다음 두 결과를 실제 frontend·API·별도 DB에서 재생했다.

| 원실행 ID | 유형 | 통과한 기능 검사 |
|---|---|---|
| `E53-full-1` | 정보 부족 | 환자 검토·승인, 의료진 조회, 양쪽 synthesis 데이터 일치 |
| `E61-full-1` | 잡음 입력 | 환자 검토·승인, 의료진 조회, 양쪽 synthesis 데이터 일치 |

재생 중 모델 호출은 비활성화했다. 따라서 위 두 건은 이미 생성한 결과의 브라우저 기능 검증이며 생성 실행 수에 더하지 않는다. 이 문서의 브라우저 성공 범위는 승인·조회·데이터 일치이며, 화면 배치 전체에 대한 판정은 포함하지 않는다.

관련 회귀·평가 테스트 실행은 193개 통과, 이후 최종 평가 테스트 재실행은 22개 통과를 기록했다. 두 실행의 검사에는 중복이 있으므로 합산하지 않는다. frontend 빌드도 완료됐다.

## 7. 해석 범위와 근거

python3 - <<'PYCODE'
import json
from collections import Counter
from pathlib import Path

data = json.loads(Path(
    'backend/eval/reports/2026-11-02-pipeline-evidence.json'
).read_text())
rows = [r for r in data['rows']
        if r['service_available'] and r['delivery']
        and (r['variant'] == 'generic' or r['api_workflow_pass'])]
assert len(rows) == 120
assert Counter(r['variant'] for r in rows) == {
    'full': 25, 'generic': 57, 'fixed': 21,
    'no_followup': 10, 'attack': 7,

def quantile(values, p):
    xs = sorted(values)
    position = (len(xs) - 1) * p
    lo = int(position)
    return xs[lo] + (xs[min(lo + 1, len(xs) - 1)] - xs[lo]) * (position - lo)

for variant in ('full', 'generic', 'fixed', 'no_followup', 'attack'):
    selected = [r for r in rows if r['variant'] == variant]
    times = [r['pipeline_seconds'] for r in selected]
    print(variant, {
        'n': len(selected),
        'p50_seconds': round(quantile(times, .5), 2),
        'p95_seconds': round(quantile(times, .95), 2),
        'calls': sum(r['budget']['calls'] for r in selected),
        'estimated_usd': round(sum(
            r['budget']['estimated_usd'] for r in selected
        ), 4),
    })
