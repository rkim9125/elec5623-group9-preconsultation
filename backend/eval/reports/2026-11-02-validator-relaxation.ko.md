# 제품 검증기 조건 완화 및 저장 출력 재검사

변경·검사일: 2026-11-02

**정상적인 불확실성 표현과 관련 없는 부정 정보 때문에 요약 전체가 거절되는 조건을 완화하고, 신체 부위별 좌우 불일치 검사를 추가했다.** 검증기는 계속 Python의 어휘·구조 규칙으로 동작한다. 새로운 LLM 검증기나 추가 모델 호출은 도입하지 않았다.

[통합 평가 보고서](2026-11-02-pipeline-integrated-evaluation.ko.md)의 원실험 결과는 그대로 보존했다. 이 문서의 수치는 **기존 모델 출력에 수정 전·후 검증기를 적용한 오프라인 재검사**다. 새로운 전체 파이프라인 실행이나 실제 사용자 전달 결과가 아니다.

## 1. 구현 변경

| 항목 | 이전 동작 | 변경 후 동작 |
|---|---|---|
| 불확실성·미입력 표현 | `does not know`, `has not been supplied`, `field is blank` 등을 놓침 | 부정 수동태, 모른다는 표현, 입력란의 공란·미작성 표현을 추가 인식 |
| 알려진 사실과 누락 출처의 혼합 인용 | 인용 하나라도 `MISSING / UNCERTAIN / SKIPPED`이면 문장 전체에 불확실성 표현 요구 | 출력의 핵심 단어가 인용된 `FILLED` 출처의 명확한 긍정 내용으로 뒷받침되고, 부정·불확실한 내용과 겹치지 않는 발췌는 허용 |
| 긴 출처의 일부 사실 요약 | 출처 어느 곳에든 부정문이 있으면 요약에도 부정 표현 요구 | 출처를 문장·절로 나눠 부정 대상과 요약의 주제를 비교. 각 출력 절이 인용된 긍정 내용과 연결되고 부정 대상과 겹치지 않으면 관련 없는 부정문의 반복을 요구하지 않음 |
| 표현의 형태 차이 | 단순 표면 표현에 의존 | 보고용 문구를 제외하고, 일부 복수형·동사형·주제어를 정규화하여 비교 |
| 좌우 정보 | 유효한 출처 ID만 있으면 `left knee → right knee`도 통과 가능 | 명시된 `(신체 부위, 좌/우)` 조합이 인용 출처에 있는지 검사. 서로 다른 부위의 좌우를 합쳐 바꾸는 경우도 차단 |
| 실패 기록 | 좌우 오류를 별도로 구분하지 않음 | 좌우 정보가 바뀌거나 추가된 경우 구분 가능한 오류 메시지 기록 |

`FILLED` 출처가 하나 있다는 이유만으로 혼합 인용을 모두 통과시키지는 않는다. 순수한 부정 답변은 계속 엄격하게 검사한다. 부정 목록의 일부가 긍정 근거로 바뀌지 않도록 쉼표나 `and`만으로 절을 나누지 않는다.

유효하고 중복 없는 현재 출처 ID, 관심사별 출처 소유권, 인용에 없는 숫자 차단, 금지된 지시·임상적 단정 검사, 언어·스키마·필수 관심사 검사는 유지했다. 실패 시 구조화 기록을 보존하는 흐름도 유지했다.

좌우 검사는 무릎·어깨·손목·발목·종아리·다리·팔·손·발·눈·귀·엉덩이·팔꿈치의 명시적 표현을 대상으로 한다. 영어와 일부 한국어·중국어·일본어 표현, `both / bilateral`, `eye_side = left` 같은 부위가 식별되는 단독 방향 값을 처리한다. 임의의 우회 표현이나 모든 해부학적 명칭을 해석하는 의미 분석기는 아니다.

## 2. 대표 판정 변화

| 출처 | 요약 | 이전 | 변경 후 |
|---|---|---|---|
| 알레르기 여부를 모름 (`UNCERTAIN`) | `The patient does not know whether they have medicine allergies.` | 거절 | 허용 |
| 알레르기 정보 미입력 (`MISSING`) | `Allergy information has not been supplied.` | 거절 | 허용 |
| `Left knee aching. No supplements.` | `The patient reports left knee aching.` | 거절 | 허용 |
| `Left knee aching.` + 별도 알레르기 미입력 출처 | `The patient reports left knee aching.` | 거절 | 허용 |
| 알레르기 미입력 + 관련 없는 정상 출처 | `No known allergies.` | 거절 | 거절 유지 |
| `Left knee aching. No supplements.` | `The patient takes supplements.` | 거절 | 거절 유지 |
| `Left knee aching.` | `Right knee aching.` | 허용 | 거절 |
| 왼쪽 무릎 통증 + 오른쪽 어깨 통증 | 오른쪽 무릎 통증 + 왼쪽 어깨 통증 | 허용 | 거절 |
| `Vitamin C 5 mg` | `Vitamin C 6 mg` | 거절 | 거절 유지 |

부분 요약을 허용한다는 것은 전체 요약에서 중요한 부정 정보를 누락해도 된다는 의미가 아니다. 이번 변경은 문장별 불필요한 거절을 줄이는 것이며, 전체 내용의 누락·정확도는 별도 평가 대상이다.

## 3. 기존 204건에 대한 대응 재검사

276개 주 분석 조합 중 제품 검증기를 사용한 **204건 전체**를 사용했다. Generic 72건에는 이 검증기가 없으므로 제외했다. 성공 사례만 골라 재검사하지 않았다.

각 실행의 마지막 요약 응답과 **그 응답 생성 당시의 요청에 들어 있던 출처·관심사·언어**를 그대로 사용했다. 원실행 213건과 크레딧 영향을 대체한 후속 63건의 조합은 [후속 근거 JSON](2026-11-02-pipeline-resumed-evidence.json)의 `combined_rows`를 따랐다. 현재 DB에서 출처를 다시 만들거나 인용 ID를 고쳐 통과시키지 않았다.

보관된 이전 검증기의 판정이 기존 전달 여부와 204건 모두 일치하는 것을 확인했다. 캡처된 요청·응답의 본문 해시도 확인했다. 재생 중 HTTP 전송을 차단했으며 **모델 호출은 0회**다.

| 조건 | 분모 | 이전 검증 통과 | 변경 후 검증 통과 | 추가 통과 |
|---|---:|---:|---:|---:|
| Full | 72 | 29 (40.3%) | **68 (94.4%)** | +39 |
| Fixed | 72 | 29 (40.3%) | **66 (91.7%)** | +37 |
| No follow-up | 36 | 17 (47.2%) | **30 (83.3%)** | +13 |
| Attack | 24 | 8 (33.3%) | **19 (79.2%)** | +11 |
| 제품 조건 전체 | **204** | **83 (40.7%)** | **183 (89.7%)** | **+100** |

거절은 **121건에서 21건**으로 감소했다. 기존 통과 83건이 새로 거절된 경우는 없었다. 추가 통과 100건은 **규칙 변경으로 검증을 통과한 수**이며, 모두 사실상 올바르다고 확정한 수가 아니다. 이번 작업에서 의미 정확도를 다시 채점하지 않았다.

남은 21건의 첫 번째 거절 사유는 다음과 같다. 같은 출력에 여러 문제가 있을 수 있어 전체 오류 수와 다르다.

| 첫 번째 사유 | 건수 |
|---|---:|
| 불확실성 보존 조건 | 8 |
| 인용 출처에 없는 수치 | 7 |
| 현재 기록에 없는 출처 ID | 4 |
| 중복 등 유효하지 않은 출처 목록 | 1 |
| 관심사별 출처 소유권 위반 | 1 |
| 합계 | **21** |

남은 거절을 모두 잘못된 생성이라고 판단하지 않는다. 예를 들어 이름 출처 두 개를 인용한 `two medicines`는 실제 항목 수 설명일 수 있지만, 현 수치 검사는 출처 값에 `2`가 없으면 차단한다. 이번 변경에서 수치 조건까지 일괄 해제하지 않았다. 알 수 없는 표현을 보수적으로 거절하는 경우도 남아 있다.

Full과 Fixed의 통과 차이만으로 AI 질문 선택의 이점을 입증하지 않는다. 수정된 제품으로 새 과제를 실행한 결과가 아니며, 질문으로 얻은 정보의 유용성이나 요약의 내용 정확도를 재평가한 비교도 아니다.

## 4. 회귀 검증

기존 경계사례 40건은 문구와 기대 판정을 바꾸지 않고 재사용했다.

| 지표 | 이전 | 변경 후 |
|---|---:|---:|
| 정상 문장 허용 | 12/20 | **20/20** |
| 정상 문장 오거절 | 8/20 | **0/20** |
| 오류 문장 차단 | 16/20 | **20/20** |
| 오류 문장 오허용 | 4/20 | **0/20** |
| 전체 기대 판정 일치 | 28/40 | **40/40** |

이 40건은 5유형의 반복 구성이고 일부 문구가 중복된다. 일반적인 오류율의 통계적 추정치가 아니다.

추가 테스트에는 불확실성의 정상 표현, 모름을 없음/있음으로 바꾸는 오류, 무관한 정상 인용을 이용한 오류 통과 시도, 부정 목록, 복합 문장의 보충제 부정, 신체 부위별 좌우 교환, 다국어의 명시적 좌우, 근거 없는 양측 확장, 수치·출처·관심사 검사, 요약 성공과 거절 시 기록 보존을 포함했다.

최종 관련 제품·평가 테스트 결과는 **841 passed, 1 warning**이다. 경고는 기존 PDF 테스트의 `pypdf.add_js` 사용 중단 예고다.

```sh
cd backend
LLM_PROVIDER=fake .venv/bin/python -m pytest tests/test_product_*.py eval/tests -q
```

최초 확대 테스트는 로컬 `.env`의 `LLM_PROVIDER=openai`와 과거 API 설정이 허용하는 `fake/azure`의 불일치로 수집 단계에서 중단됐다. `.env`나 제품 설정을 수정하지 않고 테스트 프로세스에만 `LLM_PROVIDER=fake`를 적용해 위 전체 검사를 완료했다. 앞서 수행한 부분 테스트 수는 841건에 중복되므로 합산하지 않는다.

## 5. 적용 범위와 근거

제품 코드에 반영했으며, 실행 중인 서버의 재시작이나 운영 배포는 수행하지 않았다. 새 코드가 로드된 이후의 검증부터 적용된다. 기존 저장 요약·승인본·평가 보고서는 다시 쓰지 않았다.

주요 변경 파일:

- [intelligence.py](../../app/product/intelligence.py): 불확실성 인식, 혼합 출처 예외, 부정 대상 비교, 좌우 검사.
- [pipeline.py](../../app/product/pipeline.py): 좌우 실패 사유 분류.
- [제품 회귀 테스트](../../tests/test_product_citation_validation.py): 정상·오류 쌍 및 제품 review 경로.
- [기존 경계사례 테스트](../tests/test_extended_eval.py): 알려진 오류를 기대하는 테스트에서 수정 후 기대 판정 일치를 요구하도록 변경. 원본 사례·과거 결과는 보존.
- [오프라인 재검사 도구](../validator_replay.py), [재검사 근거 JSON](2026-11-02-validator-relaxation-evidence.json): 실행별 판정, 원요청·응답 해시, 추가 통과 ID, 남은 사유, 40개 경계사례.

저장된 원실험 폴더가 있는 환경에서 다음 명령으로 재검사할 수 있다.

```sh
backend/.venv/bin/python backend/eval/validator_replay.py \
  --output backend/eval/reports/2026-11-02-validator-relaxation-evidence.json
```

**해석 한계:** 수정에 참고한 기존 합성 표본을 재사용한 회귀 검사이므로 별도 보류 표본의 일반화 성능은 아니다. 어휘 기반의 문장·주제 연결은 완전한 의미 함의를 검증하지 못하고, 불확실성 표현 하나가 문장 내 다른 단정까지 적절히 수식하는지 전부 판단하지 못한다. 좌우의 모든 우회 표현, 수치와 단위·약물 간 결합, 전체 요약의 필수 정보 누락도 완전히 검증하지 못한다. 따라서 검증 통과 증가를 사실 정확도나 임상적 타당성의 상승으로 대체 해석하지 않는다.
